# Week 4 — AI Project Deployment & Capstone

**Project:** Educational Outcome Prediction API

This end-to-end capstone demonstrates data preparation, model training, evaluation, Joblib serialization, and a Flask JSON prediction API using Python and Scikit-learn.

## Architecture

```text
STAR98 dataset → target construction → train/test split → preprocessing pipeline
→ Logistic Regression → evaluation → Joblib model → Flask /predict API
```

## Run locally

Python 3.10+ recommended.

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate
# macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
python src/train.py
python -m pytest -q
python src/app.py
```

Then open `http://127.0.0.1:5000/health`.

## API

- `GET /health`: reports whether the serialized model exists.
- `POST /predict`: JSON body must contain numeric values for `LOWINC`, `PERASIAN`, `PERBLACK`, `PERHISP`, `PERMINTE`, `AVYRSEXP`, `AVSALK`, `PERSPENK`, `PTRATIO`, and `PCTAF`.

Example:

```bash
curl -X POST http://127.0.0.1:5000/predict -H "Content-Type: application/json" -d '{"LOWINC":20,"PERASIAN":5,"PERBLACK":10,"PERHISP":15,"PERMINTE":3,"AVYRSEXP":14,"AVSALK":40000,"PERSPENK":5,"PTRATIO":20,"PCTAF":80}'
```

## Outputs

Training writes `models/educational_success_pipeline.joblib`, `outputs/evaluation_metrics.json`, and confusion-matrix, ROC, and cross-validation plots. Metrics are generated by the code; they are not hard-coded into this repository.

## Dataset and limitations

The STAR98 dataset is loaded through statsmodels. The demo target is constructed as `SUCCESS_RATE = NABOVE / (NABOVE + NBELOW)`, then split at the median. This is an educational binary label, not an official label. Offline test metrics do not guarantee performance on other populations. The project is not publicly deployed unless you separately host and verify it. Do not use predictions for consequential decisions.

## Security

Only load trusted Joblib artifacts. For hosting, use a production WSGI server, disable debug mode, validate input, apply rate limiting and request limits, and avoid logging sensitive inputs.
